## USB 恢复的同输入对照

输入为临时 capture 身份未确认到确认，以及旧 capture 失效后出现新 capture。

- **BASELINE**：身份确认前已执行一次检查；后续准备没有恢复；旧失败被锁定。
- **MODIFIED**：确认前不执行检查；确认后准备一次；失效 capture 不锁住后续准备。
- **ROLLBACK**：恢复 BASELINE 行为且原文件哈希一致；重新应用后恢复 MODIFIED 行为。

本项为使用真实 refresh/selection 代码和 capture/selector double 的定向验证，不是手机手势回放。

## 同伴断连隔离的同输入对照

相同输入为 A 移除、A 反复加入/移除、临时身份门控、同步手势门控、已退休条目再次刷新，以及 B 自身移除。探针提取生产拓扑重建、输入校验和查找方法，以采集/worker double 执行。

- **BASELINE**：A 移除后 B 画面不可见且不允许输入；B worker 被退休并关闭；身份恢复后仍返回退休条目，准备次数为 0。
- **MODIFIED**：已独立确认且尺寸唯一的 B 保留画面、输入身份与 worker；A 反复重连保持同一个 B screen；临时门控不退休空闲 worker；退休条目不再作为可用输入返回，并重新准备一次。
- **ROLLBACK**：原哈希恢复一致，重复出现 BASELINE 行为；重新应用后输出与 MODIFIED 完全一致。各次探针退出 0。
- B 自身移除仍关闭旧画面；同步手势被中断仍退休并关闭 worker。尺寸相同或未知设备不以尺寸推断放行。

该优化不意味着可以信任名义 AVCapture UID：已否定的直接 UID 方案曾在真机上将 iPhone 12 与 SE2 的画面尺寸互换，未保留该方案。

## 仍需补验

### USB 空闲会话断线后无法重新准备

根因是 worker 一旦准备成功就始终要求最终关闭回执；即使未发送输入或上次终止操作已确认释放，USB 断线丢失最终回执也会永久阻断后续准备。修复保留最新请求的精确设备释放/PING 证据，并等待进程实际退出；只读准备和纯取消不伪造持有输入。未确认按下、部分写、异机/过期回执仍保持阻断。本项不证明实际手势或文字投递成功，也不替代受控物理拔插验收。

- 同输入 BASELINE：空闲/已完成操作的 worker 退出后仍禁止 USB 重试；MODIFIED：允许安全重新准备；ROLLBACK：复现 BASELINE 且哈希恢复一致；重新应用后匹配 MODIFIED。未确认请求和过期回执在所有版本仍阻断。
- 本地应用最终构建后，iPhone 12 从旧会话释放失败恢复为 `ready`、`sessionCurrent=true`，画面 1170×2532；随后对同一完整 ID 连续两次显式“重新准备 USB”均恢复 `ready`。这是新进程及准备重建验证，不能声称已在线升级旧内存状态或已完成物理断连/实际输入投递。
- 此前物理试验中用户确认也动过另一台手机或扩展坞，不能据此认定仅 SE 热插拔使同伴中断，结论为不可判定而非隔离验收通过。
