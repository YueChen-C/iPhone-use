# 跨设备指针模型与模板复用

不同型号和 iOS 版本共用运动规划公式，每台手机保存实际测得的加速曲线。跟踪速度、指针设置、显示缩放和报告间隔都会影响曲线，因此不能仅凭机型或 iOS 版本选用另一台手机的参数。

仓库中的去身份参考数据见 [指针校准基础数据](../data/pointer-calibration/README.md)。目前收录 SE 第二代／iOS 15.4 和 iPhone 7／iOS 15.8.3 的 750 × 1334 实测曲线。2026-10-28 使用独立 USB 截图核实画面身份后，原始 HID 32 档往返实测为 SE 约 78 像素、iPhone 7 约 110 像素，不能仅凭同为 iOS 15、同分辨率直接共用。这些数值来自当次已核实的画面对应关系；后续重启又观察到 AVFoundation 捕获 UID 与实际像素来源交叉，包括独立的视频捕获，因此重连后必须重新核对实际画面来源，不能仅凭 UID 沿用此前的画面身份。自动校准脚本会尝试同分辨率候选，通过目标手机实测后才保留；主程序不按型号或系统版本直接加载另一台手机的参数。不同物理分辨率不能直接按屏幕宽度比例套用；同一台手机仅缩小预览或截图时，坐标换算不改变原曲线。

## 公共公式

窗口先将鼠标转换成手机画面的比例坐标 `(u, v)`，再得到物理像素目标：

```text
target = (u × screenWidth, v × screenHeight)
```

对于已经通过对角测试的模板，设相对 HID 报告为 `(dx, dy)`，测量表 `D[n]` 表示幅度为 `n` 的单轴报告移动的物理像素数：

```text
n = floor(hypot(dx, dy))
gain = D[n] / n                  # n > 0，且 hypot(dx, dy) 不超过测量范围
predictedDelta = gain × (dx, dy)
```

运动规划器选择使剩余误差减小的整数报告，累积预测位置，并限制报告幅度、频率和屏幕边界。未经验证的对角模型只使用单轴报告，避免直接套用错误的合成增益。这些公式对应 `RelativePointerCalibration.trackingStep`，不是一条跨所有指针设置都固定不变的像素倍率。

## 自动适配

首次连接时，主程序先判断绝对坐标是否有效。相对模式已被探测确认、且这台手机没有有效配置时，主程序自动使用 USB 画面测量：

1. 只发送不带按键的原始相对报告，在静止画面中识别指针移动前后的两个完整圆形区域。重叠、裁切、形状改变及明显背景动画不作为可靠位移。
2. 测量 1～32 档单轴曲线，小幅度使用较长报告序列以降低像素取整误差；检查反向返回、多个垂直幅度和三个实际目标落点。原生流程只启用单轴规划，不假定对角加速模型。
3. 全部通过后，按 USB 和蓝牙身份保存并热加载。已有配置直接复用；自动测量不会覆盖已有配置，也不会在同一蓝牙会话内不断重复失败测量。

这个流程不打开 Safari，不要求手机与 Mac 局域网互通，也不依赖输入法。测量时保持手机解锁、画面静止，控制窗口显示自动适配状态。窗口鼠标、键盘或 API 的实际输入会中止后台探测或测量，优先处理用户操作；若该手机仍缺少有效曲线，精确坐标操作会提示尚未就绪。其他手机仍可使用。

可通过 `/status` 的 `pointer.automaticCalibration` 查看 `state`、`measuredCounts` 和失败原因。画面不适合观测时不会保存配置。保持画面静止后，可对所有已连接且缺少配置的手机统一重试：

```sh
curl -s -X POST http://127.0.0.1:7390/calibration/auto -d '{}'
```

传入 `device` 只重试指定手机。诊断时传 `"verifyOnly":true` 会重新测量并验证，但不改已有配置；测量结果在状态中的 `distances`，`saved` 为 `false`。分辨率改变、已有曲线失效时暂不自动覆盖原配置；原生画面中指针不可见或形状无法稳定识别时，也可能测量失败，不能保证所有型号、系统和页面都能自动适配。

### Safari 诊断与候选模板

原网页测量脚本仍可单独使用：

```sh
python3 scripts/calibrate-pointer.py --auto --device '<完整设备ID>'
```

脚本通过系统搜索打开 Safari，载入临时测量页，确认页面回报的屏幕尺寸。Mac 与手机需要局域网互通，手机的硬件键盘输入源需要使用 English/US 等可原样输入 ASCII 的模式；中文输入法可能把网址转换成汉字或全角符号。测量期间保持鼠标和手机不动。

1. 先清除相对位置估计、重新归位，再检查三个目标的实际位移。原生绝对坐标或已保存的相对曲线通过检查时，直接复用，不重新测量、不修改文件、不要求重启。
2. 检查不通过时，试用同物理分辨率的基础数据，或者 `--baseline <JSON 路径>` 指定的旧设备配置。候选验证失败时恢复两个配置文件和运行时输入，再测量单轴曲线并验证垂直、对角移动。根据观测到的位移选择横向采样起点；采样触及屏幕边缘时重新归位、减少报告次数后重测，避免固定起点要求用户调整跟踪速度。不符合对角模型的手机保留单轴模式。
3. 通过 `/calibration/reload` 热加载并验证新映射后保留配置，不重启蓝牙；新映射验证失败同样回滚。普通重启、USB 重连不需要重新测量，只需重新建立指针原点。

`--force` 跳过复用检查，强制重新测量。自动打开失败时可以手动在 Safari 打开打印的网址；旧的手动流程仍然可用。

## 模板与身份

数据保存在 `~/Library/Application Support/iPhoneUse/pointer-calibration/`：

| 文件 | 用途 |
| --- | --- |
| `<Bluetooth host>.json` | 保持原有文件兼容，记录配对身份 |
| `by-screen/<USB ID 的 UTF-8 十六进制>.json` | 保存该物理手机最近一次成功测量的曲线，重新配对后仍可复用 |
| `required/<USB ID 的 UTF-8 十六进制>.json` | 绝对坐标探测失败、相对移动验证成功后保存的模式要求；缺失校准文件时仍禁止退回绝对坐标 |

两个文件使用原有 JSON 结构：`host`、`screenID`、`screenWidth`、`screenHeight`、`reportInterval`、`distances`，以及可选 `vectorModel`。稳定模板的 `host` 是测量时的身份，加载时会重新绑定到当前已确认的蓝牙身份。

同一 USB 身份记录的稳定模板优先于旧蓝牙身份下的曲线，避免多份历史文件让重连复用变得不明确。模板加载会验证记录中的 USB 身份和曲线有效性，分辨率检查由坐标操作执行；这些检查无法证明 AVFoundation 当前像素来源确实属于该 UID，重连后仍需核对实际画面与设备的对应关系。不同手机不因分辨率相同就互相套用参数，身份有疑点时保留已有曲线，不能据此改写模板归属。

自动适配需要实际输入和可靠观测；指针未移动、测量不稳定或跟踪速度使测量越过屏幕边缘时会停止，保留已有模板。网页诊断另外要求页面可达。已经通过检查并不保证长时间相对运动绝无漂移；原点丢失时应归位，曲线变化时才需要重新测量。


## 捕获画面身份

多台手机的 AVFoundation 名义 UID 不保证始终对应其实际像素来源。主程序通过 macOS 自带的 `MobileDevice.framework` 枚举 USB 设备，严格按 USB UDID 选择目标，在已信任的连接上访问 `com.apple.mobile.screenshotr` 服务，独立截图并与捕获画面匹配。无需安装 `libimobiledevice`、`idevicescreenshot` 或 Homebrew，应用也不打包这些依赖。最多比较三轮，要求两轮得到一致且唯一的对应关系后才应用已经确认的映射。该过程不发送手机输入，也不改曲线，在捕获拓扑变化或显式 `/match` 重试时运行；部分校验、校验失败或截图服务不可用时，新增 BLE 会话也触发一次重试。同一会话的多个订阅回调合并处理，不在视频帧处理或状态轮询中重复执行。

系统设备接口不是公开稳定的 API，通过运行时加载框架和所需符号检测能力；框架或符号缺失时报告 `unavailable`。调用在同一可执行文件的隔离工作进程中完成，不启动窗口、蓝牙或 HTTP 服务，截图超时设为 8 秒，随后仅结束自己的工作进程并删除临时截图。设备缺失、未信任、锁屏或传输失败属于校验失败，不等同于缺少截图服务；程序不会自动配对、挂载开发镜像或改用其他手机。部分 iOS 版本不提供该服务，仍按以下能力限制处理。

`GET /status`、`GET /devices` 和 `POST /match` 返回的 `capture` 包含 `identityState`、`permitsPointerAssociation` 和 `screens`。每个 `screens` 项的 `physicalID` 是对外使用的 USB 身份，`sourceID` 是提供像素的 AVFoundation 名义 UID，`identityVerified` 表示当前映射是否已确认；两者可以不同。

每轮独立比较之间等待 0.5 秒，避免截图服务暂未就绪时立即耗尽三轮机会。一次验证完全失败后，等待 3 秒自动再验证一次；仍失败则停止。拓扑改变会废弃旧重试，不做无限轮询。

| `identityState` | 含义与处理 |
| --- | --- |
| `singleDevice` | 当前只有一个捕获源，无多源交叉歧义；不运行独立截图比较。 |
| `pending` | 多源身份验证进行中，暂停匹配与输入。 |
| `verified` | 两轮独立截图确认唯一完整映射，可继续指针关联。 |
| `partiallyVerified` | 仅部分手机的画面已确认，只放行这些手机的关联与输入。 |
| `failed` | 独立截图或图像比较失败，无法证明任何可靠映射；阻断匹配与输入，保留已有曲线。画面稳定、可区分后可显式调用 `/match` 重试。 |
| `unavailable` | 系统设备框架或所需符号不可用，或所有手机均缺少截图服务。名义映射仍未独立验证；允许按受限回退流程继续运动匹配，不代表物理 USB 身份已确认。 |

运动匹配只能证明哪个蓝牙 host 驱动当前画面；`unavailable` 时不能把它当作 USB 像素来源的独立证明。已有曲线应保留，不能靠重测或交换参数掩盖身份疑点。

在物理画面身份已确认后，运动关联绑定持续在线的物理 USB ID 和 BLE 会话，视频源实例单独控制画面与输入对象的生命周期。另一台手机拔插时，保留原手机的蓝牙关联；视频源未变化时也保留原窗口输入对象。AVFoundation 重新分配视频源时，重新绑定画面并清除指针位置估计，但无需重新证明同一物理手机的蓝牙归属。拓扑复核期间暂缓输入，界面显示“蓝牙已连接，画面身份待确认”，不显示蓝牙未匹配遮罩；映射重新确认后恢复。原手机 USB 消失或 BLE 会话改变时仍需新运动证据；独立截图完全不可用时撤销继承的证明，按受限回退流程重新匹配，未验证的名义映射不能继承物理身份。

## 首次连接

蓝牙连接与 USB 画面需要单独关联。主程序用不依赖曲线的相对鼠标报告描绘矩形，检查四个角上指针的局部到达、离开及回到起点的变化，且仅有一块画面命中，才自动匹配。远处无关动画不会单独否决这条局部轨迹；画面过于动态、无法提取可靠轨迹时仍会停止。一次完整相对身份探测发送 48 份无按键报告，其中 32 份用于预备位置、16 份描绘矩形；两个目标区域的像素变化只用于候选排序，不能证明身份。已有曲线的设备跳过绝对坐标和大幅归位测试；新设备另外以绝对坐标往返检验输入能力。该过程只移动、不点击，不会把“蓝牙已连接但尚未匹配”显示成“蓝牙未连接”。身份验证不会覆盖已有曲线；确需相对模式且缺少曲线时，随后自动测量。每轮每个蓝牙 host 只采样一次证据。相同 USB 捕获与蓝牙会话组合最多安排一次延迟探测重试；再次尝试需重新连接或显式调用匹配。用户输入会取消当前探测和待执行重试，避免反复移动指针。测量失败时保留键盘输入，并拒绝精确坐标操作。

窗口鼠标离开手机画面时，会取消待执行的悬停目标；相对模式的归位和追踪过程会检查取消状态，避免继续追赶已经失效的位置。

连接未就绪时，鼠标进入、经过或离开连接提示层不取消后台匹配。可以实际接收输入的窗口仍由鼠标活动优先中止后台运动；点击、键盘和显式 API 操作沿用主动取消行为。

已证明关联的手机只取消自身输入会话的后台运动，操作它不会取消另一台手机的发现。未关联手机的主动输入仍会取消本轮发现；运动证据只跟踪实际参加本轮探测的输入会话。


### 换机与截图服务不可用

多设备核验逐台区分截图服务不可用和图像不匹配。某台手机未启用 `screenshotr` 时，继续验证其他手机；若两轮均得到相同的唯一对应，且只剩这一台不支持截图的手机和一条有内容的视频流，按排除法补齐映射。最后一条视频流允许文字稀疏、对比度较低的设置页，它无需独立识别手机，但仍需有可见内容，不能是纯色或少量孤立噪点。截图失败、黑屏或图像矛盾不能使用排除法。

无法补齐完整映射、但部分手机的对应关系已经连续两轮确认时，`capture.identityState` 为 `partiallyVerified`。只有这些手机可以继续蓝牙匹配和输入；其余手机保留预览。`capture.screens[].permitsPointerAssociation` 表示每台手机是否允许关联输入。USB 换机仍需新手机自行建立蓝牙连接，拔掉 USB 不会自动断开原手机的蓝牙。

某条采集流尚未收到首帧时，也允许保留其他画面两轮独立确认的对应关系；缺失的视频流不能用排除法补造。USB 热插拔后，若采集流始终没有画面，程序在身份复核后仅重启该空流一次，并重新校验全部画面，防止启停采集流造成像素来源变化。没有帧的同一采集实例不会持续自动重启；该过程保留仍在线物理手机的蓝牙关联与校准。
